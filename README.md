### Project Context

The healthcare sector is undergoing a rapid digital transformation where leveraging medical data has become essential for improving the quality of care and institutional performance. The CHU (Cloud Healthcare Unit) group initiated this project to build its own data warehouse to harness the vast amount of information generated by its systems.

The goal is to overcome Big Data challenges (volume, variety, velocity) by creating a scalable, secure, and high-performance architecture to integrate, store, and analyze heterogeneous data (medical records, patient flow, service tracking, etc.).

### Objectives

This project aims to deliver a complete solution to:

1.  **Integrate data** from distributed sources (PostgreSQL DB, CSV/FTP files) into a single, persistent source.
2.  **Model and store** this data in a Data Warehouse to meet analytical needs.
3.  **Analyze and visualize** the data to answer specific business questions.
4.  **Propose a modern architecture** and toolset (ETL, storage, BI) that ensures security, scalability, and cost-effectiveness.

### Solution Architecture

The platform implements a modern Data Lakehouse architecture, orchestrated by Docker Compose. Data follows an ETL (Extract, Transform, Load) path through three logical layers in the Data Lake (MinIO):

-   **Bronze Layer**: Raw data is ingested from source systems (PostgreSQL, CSV) and stored in Parquet format without major transformation. It serves as a faithful, timestamped copy of the source.
-   **Silver Layer**: Data from the Bronze layer is cleaned, normalized, deduplicated, and enriched. Data quality and business rules are applied at this stage.
-   **Gold Layer**: Data from the Silver layer is aggregated and modeled into a star schema, optimized for analytical queries. These fact and dimension tables directly feed the BI dashboards.

### Technology Stack

-   **Pipeline Orchestration**: Apache Airflow
-   **Data Processing**: Apache Spark (PySpark)
-   **Data Lake Storage**: MinIO
-   **Data Warehouse (Metastore)**: Apache Hive Metastore
-   **Distributed SQL Query Engine**: Trino
-   **Business Intelligence & Visualization**: Apache Superset
-   **Containerization**: Docker & Docker Compose

### Data Pipeline (Airflow DAG)

The main pipeline is defined in `airflow/dags/chu_docker_pipeline.py`.

-   **`chu_docker_pipeline`**: This DAG orchestrates the execution of the Bronze, Silver, and Gold Spark jobs.
    -   It uses Airflow's `DockerOperator` to run each Spark job in its own isolated container, ensuring reproducibility and dependency isolation.
    -   The tasks run sequentially: `bronze` -> `silver` -> `gold`.
    -   The DAG is scheduled to run daily at 2:00 AM but can also be triggered manually from the Airflow UI for on-demand executions.
